# Site instructions

- seedypod/core's `docs/` is the source of truth. Pin source references to a core commit when documenting behavior.
- Imported pages are generated by `scripts/import-docs.mjs`; change core's docs and re-import instead of editing them.
- The pin map has been checked against the stock Gardyn 3.0 firmware and partly probed on a board (core's `docs/hardware/pin-map.md` has the status). Never present unprobed hardware behavior as verified; wait until core's docs mark it probed.
- Preserve real product screenshots. Do not draw or fabricate product UI. Capture from the demo build (`scripts/capture-core.mjs`), or, for a worked example such as MCP's Plan from an order, from a real local core run that the manifest records.
- Media source revisions, dimensions, methods, and SHA-256 checksums live in `capture/manifest.json`.
- Run `pnpm check` before publishing. It verifies media, static export, types, routes, links/fragments, search, and responsive overflow.
- Pages deploys from `main`; pull requests must pass `Build and browser checks`.
- Write `seedypod` in lowercase everywhere in authored copy, including headings, metadata, and alt text.

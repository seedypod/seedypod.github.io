# Developer documentation

seedypod lives in one repository, [seedypod/core](https://github.com/seedypod/core): a Rust workspace for the hardware daemon in `hal/`, and TypeScript for the server (`server/`, `src/`) and the web UI (`web/`). It mirrors [sleepypod](https://sleepypod.github.io/developers/workflows/)'s conventions (branching, CI, releases, ADRs, a Vercel demo and this Nextra site) so tooling and habits carry over.

## Start here

```sh
pnpm install && pnpm dev                 # core :3000 (simulator), web :5173
pnpm test · pnpm tsc · pnpm lint         # TypeScript checks
pnpm hal:test                            # Rust
cargo run --manifest-path hal/Cargo.toml -p hald -- --sim --stdout --ticks 3
```

`dev` is the integration branch and `main` is release-only. Commits are conventional, and every PR to `main` must be titled `feat:`, `fix:`, `perf:` or `revert:` because it cuts a release. Read the repository's `AGENTS.md` and the [ADRs](/developers/adr/) before changing safety or contract code.

## Clients

Everything a client needs is core's API: tRPC (with the generated REST facade) and the live event stream at `/api/ws`. The web UI ships with core. The [iPhone app](/ios/) lives in its own repository, [seedypod/ios](https://github.com/seedypod/ios) (SwiftUI, AGPL-3.0); it ports sleepypod's iOS transport and finds units over Bonjour (`_seedypod._tcp`), as recorded in [ADR-0017](/developers/adr/0017-ios-client/).

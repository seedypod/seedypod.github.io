# Developer documentation

seedypod lives in one repository, [seedypod/core](https://github.com/seedypod/core): a Rust workspace for the hardware daemon in `hal/`, and TypeScript for the server (`server/`, `src/`) and the web UI (`web/`). It mirrors [sleepypod](https://github.com/sleepypod)'s conventions (branching, CI, releases, ADRs, a Vercel demo and this Nextra site) so tooling and habits carry over.

<Callout type="warning">
  **Pre-hardware.** Everything is tested against the simulator and a local Mosquitto broker. The
  real drivers compile for both Pi targets, but their register sequences, timings, the PWM overlay
  and the [pin map](/developers/hardware/) are unverified until Phase 1 is done on a real unit. See
  the [handoff](/developers/handoff/#1-what-exists) for exactly what is and is not proven.
</Callout>

## Start here

```sh
pnpm install && pnpm dev                 # core :3000 (simulator), web :5173
pnpm test · pnpm tsc · pnpm lint         # TypeScript checks
pnpm hal:test                            # Rust
cargo run --manifest-path hal/Cargo.toml -p hald -- --sim --stdout --ticks 3
```

`dev` is the integration branch and `main` is release-only. Commits are conventional, and every PR to `main` must be titled `feat:`, `fix:`, `perf:` or `revert:` because it cuts a release. Read the repository's `AGENTS.md` and the [ADRs](/developers/adr/) before changing safety or contract code.

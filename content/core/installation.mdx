# Install seedypod on a Gardyn

<Callout type="error">
  **Phase 1 is not done: nothing here has run on a real Gardyn yet.** The install scripts' Raspberry
  Pi OS steps, the pin map and the I²C addresses are documented assumptions. Follow at your own
  risk, and **back up the stock card first** so bricking is a five-minute reflash.
</Callout>

seedypod runs on the Raspberry Pi already inside the unit: early Gardyns use a Pi Zero W, later ones a Pi Zero 2 W. The default setup runs both `hald` and core on that Pi. You can also run core on any other machine on your LAN and point it at the daemon ([deployment topologies](/developers/architecture/#deployment-topologies)).

<Steps>

### Back up the stock card

1. Power off the unit, open the base, and remove the Pi's microSD card.
2. On a computer, image it and keep the image somewhere safe:

```sh
sudo dd if=/dev/YOUR_CARD of=gardyn-stock.img bs=4M status=progress
```

This image is your way back to the stock Gardyn software. Do not skip it.

### Flash Raspberry Pi OS

In Raspberry Pi Imager, choose **Raspberry Pi OS Lite**: 64-bit for a Zero 2 W, Pi 4 or Pi 5, 32-bit for the original Zero W. In the advanced options set the hostname to `seedypod`, enable SSH and add your Wi-Fi. Reseat the card, boot, then connect:

```sh
ssh pi@seedypod.local
```

### Enable I²C and install the hardware daemon

```sh
sudo raspi-config nonint do_i2c 0
curl -fsSL https://raw.githubusercontent.com/seedypod/core/main/scripts/install-hal | bash
hald --check
```

The installer detects the CPU, downloads the matching `hald` binary from the latest GitHub release, writes a commented `/etc/seedypod/hal.toml`, creates a `seedypod` system user in the `gpio`, `i2c` and `video` groups, enables the PWM overlay for the grow light (one reboot needed), installs `fswebcam`, installs the Mosquitto MQTT broker on `127.0.0.1:1883` (reachable only from the Pi itself), and enables `hald.service`. `hald --check` validates the config and prints the devices it plans to use. See the [hald reference](/developers/hal/#install) for options.

### Install core

On the same Pi, or on any machine on your LAN:

```sh
curl -fsSL https://raw.githubusercontent.com/seedypod/core/main/scripts/install | bash
```

Core listens on port 3000. If `hald` runs on another machine, set `HAL_MQTT_URL` in `/etc/systemd/system/seedypod-core.service`. Then open `http://seedypod.local:3000/`.

The installer accepts `--branch dev` to install the rolling development build, and `--prefix` to change the install location (default `/opt/seedypod`).

### Connect Home Assistant (optional)

Home Assistant needs to reach the broker `hald` publishes to. Pick one:

- **Home Assistant on another machine, using the unit's broker.** Run the installer with `--mqtt-lan`: `curl -fsSL https://raw.githubusercontent.com/seedypod/core/main/scripts/install-hal | bash -s -- --mqtt-lan`. The broker then also listens on port **1884**, password-protected, and the installer prints the `homeassistant` password once. In Home Assistant, add the **MQTT** integration with host `seedypod.local`, port `1884`, user `homeassistant` and that password.
- **Home Assistant's own broker** (the Mosquitto add-on). Install with `--no-broker` instead, then set `mqtt_url`, `mqtt_username` and `mqtt_password` in `/etc/seedypod/hal.toml`, and `HAL_MQTT_URL=mqtt://USER:PASS@homeassistant.local:1883` in `/etc/systemd/system/seedypod-core.service`. Restart both with `sudo systemctl daemon-reload && sudo systemctl restart hald seedypod-core`.

Either way, the Gardyn appears through MQTT discovery. See [Home Assistant](/core/home-assistant/).

</Steps>

## First things to set

Open **Settings** in the web UI and set:

- **Timezone**, so schedules fire at the right local time.
- **Tank calibration**: the ultrasonic distance in centimetres when the tank is just filled, and when the pump would run dry. These turn the distance reading into a tank percentage.
- **Grow reminders**, if the defaults (thinning at day 14, root check at 21, harvest at 35, nutrients every 7 days) do not suit your plants.

Then add a [light curve and a watering schedule](/core/schedules/).

## Change Wi-Fi

No keyboard needed. Hold the unit's button for **10 seconds**. At 1 second it acknowledges any latched fault; keep holding. The unit then opens an open hotspot named `seedypod-setup-xxxx` for 15 minutes:

1. Join `seedypod-setup-xxxx` from a phone.
2. Open `http://10.42.0.1:3000/wifi`, pick your network, enter its password, and press **Join**.
3. The unit leaves the hotspot and joins your network. Rejoin your network on the phone and open `http://seedypod.local:3000/`.

If the password was wrong, the hotspot comes back and the Wi-Fi screen says why. On your network, **Settings → Wi-Fi** does the same without the button. The hotspot is open because pressing the button already proves someone is at the unit, and it closes itself after 15 minutes.

## Uninstall

```sh
sudo systemctl disable --now seedypod-core hald
sudo rm -rf /opt/seedypod /etc/systemd/system/seedypod-core.service /etc/systemd/system/hald.service
```

Or reflash the stock image from the first step.
